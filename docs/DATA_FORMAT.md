# Data format

The executable workstation uses **FM1P version 4** (`storage/format.c`), a complete self-contained project container. It is independent of the initial library's `FZH1` additive-only recipe. It contains no pointers, raw C struct layouts, calibration or firmware update addresses.

The 24-byte little-endian header contains magic `FM1P`, uint16 version 4, uint16 header length 24, uint32 payload length, uint32 payload CRC32, uint32 generation, and uint32 CRC32 over the first twenty header bytes. Every length must match exactly; unknown versions, noncanonical booleans, invalid references/ranges, duplicate IDs and non-finite numbers reject before publication. IEEE binary32/binary64 scalars are explicit and checked at compile time. The codec in `format.c` defines exact field order; records are length-delimited.

The payload saves project tempo/clock, four FX configurations (including separate return mute), immutable PCM16 mono/stereo assets with source/rate/cycle/checksum, instruments and all 48 harmonic levels, regions/markers/mapping/envelopes/modulation/loops, track mixer, arpeggiator settings and 64-entry ordered chains, sparse patterns/events/frozen asset routing, song entries, and original sample bake recipes with the exact track sends that ALL bake cleared. Pattern notes and source PCM remain available to unfreeze/unbake after reload. Undo transaction pointers/history and their dependency snapshots are runtime-only. Superseded cycle revisions carry a retired flag; the single owner reclaims them only after current/undo/redo and active reader pins expire. Ordinary retained PCM/event storage stays conservative.

Version 3 appends each track’s arp mode/division/octaves (three uint8 values), gate/swing/probability (three binary32 values), and latch/played-order (two canonical booleans) after its MIDI channel. Version 2 files and local save generations remain readable; their tracks receive the default Off/1/16/one-octave/50%-gate/100%-probability configuration. New writes use version 4. The `tests/fixtures/project-v2-before-arp.fzb` fixture is an actual pre-change export and tests this migration. Unknown versions still reject.

Version 4 adds instrument type 2, Synth, alongside Multi Sample (0) and Sample (1), without changing the version 3 payload layout. Synth regions must reference cycle assets. Versions 2 and 3 still load; pitched instruments containing only cycle assets migrate to Synth. Ordinary or mixed sample instruments retain their sample type and editing pages. New Synth creation opens a playable sine oscillator; its EDIT pages are oscillator, amplitude envelope, filter and LFO. Sample and Multi Sample enter USB capture directly without a source chooser; their eight edit pages omit the synth oscillator page. Trim, loop, sample mixing, mapping and render pages remain available on sample instruments.

IDs are stable uint32 handles; zero is invalid, next-id exhaustion is rejected. Object/region/voice ceilings are distinct from PCM/working-memory budgets. Decoding allocates a staging project from remaining budget, validates everything and only then replaces the old project. The simulator additionally prepares engine/sequencer allocations before swapping owners. Malformed or oversized restore leaves the current project intact. This development format does not silently migrate the unpublished workstation v1 prototype or initial FZH1 recipe; retain old files and use their matching decoder when migration is needed.

Host saves (`storage/journal.c`) alternate `PREFIX.0` and `PREFIX.1`. A generation is fully written, verified and fsynced with directory durability before success is reported; load picks the newest valid complete generation. Fault tests interrupt each write/durability step. SAVE queues during playback. This POSIX journal is not used as a pretend flash driver; on-device persistence is still pending.

The transport-independent import receiver accepts bounded, numbered CRC-protected chunks, rejects conflicting duplicates and only publishes a fully validated project after explicit replacement confirmation. USB SysEx framing/device transfer is not implemented. WAV import accepts validated PCM16 RIFF data and performs explicit SRC for ordinary samples. Cycle import uses the point count as its period; it does not infer undocumented EPROM encodings.

Legacy `FZH1` remains tested in `firmware/dsp/additive.c`: magic, version 1, count 48, uint16 levels 0..256, uint16 point count and FNV-1a checksum. It is an additive recipe, not a complete workstation backup.
