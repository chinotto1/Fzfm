# Controls and workflows

Display colors have consistent meanings: blue selects a row or marks an empty cell, green marks filled sounds and meters, amber marks focus/values, and red marks recording or clipping. Primary labels and values use larger bold pixel text. The capture page shows all sixteen slots, the input meter and the current setting together; knob 1 still chooses the setting and knob 2 edits it.


The simulator uses the same UI, sequencer and audio engine as the development board adapter. The browser adds a visible New track menu, graphical touch editors, local file import/export, microphone recording and a synthetic test input. Core operation is designed for the physical panel; the browser is optional.

## Start and play

On the public iPad emulator, start with **+ New track** and choose Synth instrument, Drum kit, Sampled instrument, Additive synth, Preset wave or Drawn wave. **Playing track** selects an existing track. **Sampler** opens a Simple/Multi instrument selector, sixteen waveform slots, Capture test sound, Record microphone and Sample from Files; tap a slot to choose where the take goes. Replace, audition, delete and undo are on that page; **Finish sampling → Play** returns to the keys. Microphone/file takes are limited to ten seconds and stay on this device. See [WEB_EMULATOR.md](WEB_EMULATOR.md) for the complete touch workflow. **Sequencer** opens the touch piano roll: tap to add, drag to move, resize the right edge, or edit pitch/start/length/velocity directly. Record, retrospective capture, patterns, tempo, swing and reversible Quantize are on the same page. Off restores the performed timing. The physical panel sequence follows below.

From an empty HOME, tap SCL to create an instrument. Choose MULTI SAMPLE, SAMPLE or SYNTH with knob 1 and confirm with SCL. A track and empty pattern are created automatically. SAMPLE and MULTI SAMPLE open USB audio capture immediately: there is no source selection or extra confirmation. SYNTH opens a playable sine oscillator. HOME returns to playing; ALGORITHM selects a track. The four HOME knobs control cutoff, resonance, volume and pan. SELECT is rotary: it has no invented push. This development mapping uses the physical **SCL button as logical SEL**.

In MULTI SAMPLE capture, separated hits fill sixteen consecutive keys. Unrecorded slots are silent and reserve no PCM. Knob 1 selects capture settings; other knobs change the selected value. Choose input L/R/summed mono, start/stop thresholds, silence duration, pretrigger, minimum/maximum take and manual mode. SCL starts/ends manual capture or applies retry/skip/resume rows. REC also controls manual capture. Press flashing **OCT+** to finish immediately and open playable HOME without an octave change. Hold HOME → USB CAPTURE reopens capture on the same sampled track. A SAMPLE capture uses the chosen root; subsequent anchors can divide the keyboard automatically. The host defaults to a one-second maximum take; the board's initial maximum is 4,096 frames (113.78 ms).

The sampling page shows free/total shared sample memory, remaining recording time and approximate additional sample counts. Browser estimates show 1-second and 10-second sounds; the panel shows a 1-second count. These use mono PCM16 at 36 kHz (72,000 bytes/second), after allowing for one staging take (ten seconds in the browser; MAX TAKE on the panel). Free bytes include all current audio allocations; undo may retain replaced or deleted sounds. Counts estimate audio capacity across the project, not free slots: each instrument still has sixteen slots and working memory can limit new objects. The readout is explicitly labelled as emulator memory: its 16 MiB audio budget is a host safety limit, not a measurement of physical FM1 RAM or flash. The provisional firmware profile limits audio to 128 KiB within a shared 224 KiB heap; usable physical capacity is unverified. Routine OK status messages are hidden on every page; errors, save notices and meaningful instructions remain.

In the browser, **Send test hit** exercises SRC and the real capture state machine. It simulates a host source; it does not enumerate USB. **Import PCM16 WAV** creates a SAMPLE instrument; **Import single cycle** treats its point count as one period. The core uses 36 kHz, with explicit input conversion. Cycles are tuned from their length, not their file's claimed period.

Note keys play on HOME/EDIT/MIXER/FX/ARP/PIANO ROLL. Pickers intercept them silently. On a phone, scroll the keyboard horizontally. Drag a rotary control up/down, scroll over it, or focus it and use arrow keys. Each rotary has a 48-pixel touch target and a moving indicator; there are no adjacent +/− buttons. Shift + arrow or Page Up/Down changes ten steps. Sound starts automatically where allowed, otherwise with the first normal tap or keyboard note. Sound on/off mutes explicitly; an explicit mute survives app switching and later control gestures. Keyboard shortcuts: Escape HOME, Enter SCL, space PLAY, E EDIT, R REC, G GLO, F FX, A arpeggiator, S SAVE; Z X C V B N M play notes.

## Arpeggiator

ARP opens settings for the playing track. The first page’s four knobs control Mode, Rate, Octaves and Gate. Tap ARP again for Swing, Probability, Hold/latch and Note/Played order. The browser’s **Arpeggiator / ARP** page shows all eight settings together. Modes are Off, Up, Down, Up–Down, Random, Played Order, Repeat Last, Down–Up, Up+Octave, Converge, Diverge, Pinky, Thumb, Walk and Chord (up to four simultaneous notes). Rates span 1/4–1/64, with triplets. Range is 1–4 octaves.

Play a chord on the local or MIDI keyboard. Arpeggiation follows the project BPM with PLAY stopped or running; enabling it establishes the internal tempo so recording the arp cannot re-infer another BPM. Hold keeps released notes and replaces them when a new chord starts. Sustain holds input notes while gates remain independent. Stop clears sounding/latched arp notes. With Mode Off, keys play normally. Recording and retrospective history contain the generated notes and gates you hear. A bounded live pool admits eight arpeggiating tracks and sixteen held notes per track; overflow is reported. Settings are saved per track. Hold/latch applies while a mode is active.

Hold HOME for the commands menu; releasing HOME after a hold keeps that menu open. A HOME tap still cancels a picker or returns home. ARP always opens arpeggiator settings.

## Record and arrange

Tap REC to arm a free take. The first real note starts it; tap REC again to close it at the button-down time. Timing analysis offers tempo/length candidates. Existing musical tempo and an external clock retain ownership. Hold REC for retrospective MIDI, ending at the hold's original down edge. Hold HOME → TAKE TIMING exposes alternatives; knob 1 selects and SCL applies. History is bounded; overflow/ambiguity is reported rather than hidden.

SEQ opens PIANO ROLL first, then cycles STEP → PATTERNS → SONG → PIANO ROLL. The roll displays recorded/live-MIDI notes and gates on the instrument screen and browser. Knob 1 selects time, knobs 2–4 edit a selected note’s pitch/length/velocity; SCL adds or deletes at the cursor. Tap EDIT to toggle time-move mode, then knob 1 moves the selected note. PRESETS selects previous/next performed notes, including short off-grid notes; SELECT scrolls pitch and OCT ± moves the view and playable keyboard together by an octave. Existing raw timing and frame stamps survive pitch/velocity edits. The initial pitch view fits the phrase, up to four octaves. In STEP the sixteen white keys toggle notes; SCL opens a silent note picker. Knobs select step, note, velocity and duration. The first black key is rest; the second ties the selected step to the preceding same-pitch note, removing its retrigger and extending the original gate. Select the target step with knob 1. OCT buttons change page. Hold HOME → STEP DETAIL edits probability/microtiming or applies a latched parameter lock. PATTERN SETTINGS edits length, rate, swing, quantization and internal tempo. Motion recording records the underlying track controls.

In PATTERNS a white key selects/queues its pattern, creating empty metadata when needed. Hold two white keys to make a range chain. Hold HOME → CHAIN APPEND appends the selected pattern to the saved ordered list; CHAIN PLAY starts that order; CHAIN CLEAR removes it. Copy a pattern, select a destination, then paste; an occupied destination requires confirmation. HOLD SCL undoes it.

In SONG, SCL inserts the current scene into an empty song or queues a section. Knobs choose section, bars, repeats and selected-track pattern. Commands opened by holding HOME insert, delete, duplicate, move sections and mute the selected track within a section. RECORD ARRANGEMENT records actual pattern/mute changes during playback; FINISH ARRANGEMENT publishes the song as one undoable edit. It uses a bounded 64-section working buffer and needs free metadata RAM.

## Edit

Tap EDIT to enter the editor. Sampled instruments cycle **SAMPLE, LOOP, MIX, AMP, FILTER, MOD, MAP, RENDER**. Synths cycle **WAVE, AMP, FILTER, MOD**; their oscillator choices are Additive, Preset wave and Draw. SELECT chooses ALL or SAMPLE 01–16. Knob 1 always selects a row; knobs 2–4 match the footer labels. Rows/tab/scope are remembered separately for each instrument. Empty targets report NOT FOUND. Destructive actions request confirmation; HOME cancels a picker before leaving its screen.

ALL markers use normalized percentages of each region; ONE markers use absolute frames. Numeric entry opens only after SCL on a numeric field. White keys supply digits, backspace, minus, decimal, cancel and accept as displayed. Note/range/sample pickers never play or enter MIDI history. Hold EDIT and choose a white category key for the next DRUMS/SYNTH/PAD/LEAD/etc. name. The release does not cycle a tab.

SAMPLE edits markers, level, reverse playback, root, tuning and destructive operations. MIX chooses source B and adjusts source gains, frame offset/tuning, crossfade length/law, then executes Mix Write/Cross-Mix. AMP/FILTER edit up to eight stages, sustain/release, time, level, scaling and copy envelopes. LOOP edits up to eight forward program sections, repeat/jump/release actions and crossfades. Reverse playback currently bypasses forward loop programs. MOD edits rate/depth/shape/destination and free-run versus note retrigger. Shapes are sine, triangle, square, saw and Sample & Hold. Sample & Hold chooses one bipolar random level per cycle: Rate sets the step frequency and Depth scales the modulation. Retrigger restarts a repeatable per-sample sequence on each note; Free running shares the current sequence step across notes from that sample. Region/envelope edits are read by new notes; track controls act on held notes.

ENV/AMP and FILTER display envelope curves with sustain/release markers; MOD displays one second of the current LFO shape at its rate/depth. The browser provides larger plots and named time/level/shape fields.

WAVE exposes all 48 additive levels (knob 2 selects harmonic, knob 3 changes level), recipe normalization/application, preset waves and point drawing/smoothing/clearing. Harmonic/table edits publish immutable assets and held cycle voices crossfade for 64 frames, preserving phase. Presets offer sine/triangle/saw/square with 600/1,024 points. WAVE and oscillator selection belong to SYNTH. SAMPLE and MULTI SAMPLE always use USB capture and never offer alternative sources. Cycle extraction and shared-asset attachment remain available through the core API. MAP supports root/range/base/choke/pan/send trims and automatic zoning. Manual key ranges take priority over automatic zones. MAP → DELETE SAMPLE removes the ONE region after confirmation, recomputes zones and retains PCM for sounding voices/undo; unbake a baked region before deleting it.

RENDER bakes a one-shot sample or freezes a pattern after explicit isolated-render confirmation. Bake is a final stereo render; it requires all active sends to avoid routing wet audio through remaining sends. Shared nonlinear bus interactions cannot be decomposed exactly into independent samples. Pattern notes remain for unfreeze. Sample originals and routing recipes survive project save/reload for unbake. ONE bake leaves other sounds' track sends in place; ALL clears only selected sends on that track. These operations need temporary audio, engine and metadata space; memory rejection leaves old material/routing valid.

## Mix, undo and save

GLO opens the mixer: knob 1 track, knob 2 level, knob 3 pan, knob 4 selected send. Further GLO taps cycle the send. SCL mutes; hold GLO toggles solo. Vertical channel strips show levels, pan, mute/solo and voice peaks; the selected send is highlighted. FX selects one of four project slots: delay, reverb, chorus and character. Knob 1 selects the named parameter; knobs 2/3 edit and knob 4 pans its return. Input bypass stops new input while allowing tails; return mute silences only that return. RELEASE UNUSED FX actually frees buffers only after checking tails, active readers, stored patterns and automation.

Hold SCL undoes one transaction; Hold HOME → REDO reapplies. Continuous knob gestures coalesce for 250 ms when they touch the same fields. Undo is bounded (host eight transactions, board profile two); ordinary PCM/event buffers remain budgeted until project disposal. Superseded cycle versions are reclaimed only when current regions, bake originals, undo/redo states and sounding/crossfading voices no longer reference them. Continuous waveform edits therefore do not consume one permanent asset slot per knob step. PANIC releases voices after dropped input.

SAVE is queued during playback and commits on stop in the host simulator. Local saves alternate two CRC-protected generations. Hold HOME → LOAD PROJECT requests replacement confirmation. Export project downloads all dependencies; restore validates and prepares a full replacement before swapping, preserving the current project on malformed input. Export a backup before closing a session with unsaved changes. The native simulator starts empty; load the local save or restore a backup explicitly. Native files stay on the loopback machine. The public web emulator restores its IndexedDB save automatically on return; SAVE is local to that browser, and Export project downloads a backup to Files.

On-device project persistence and device transfer are not qualified. The target SAVE callback returns UNSUPPORTED and retains VOLATILE status; it never pretends RAM survived power loss. See REQUIREMENTS_STATUS.md for remaining device/release work.

## Hardware installation and recovery

Open the emulator header’s **Hardware installer & recovery** link in Chrome or Edge on Windows/macOS/Linux. The separate page identifies one connected FM1, offers Skiff 1.3.2 / SLOOP 2.7.1 / official V15 recovery targets, verifies a local `.fwsc` by exact size/identity/SHA-256, and requires a backup acknowledgement plus final review before a hardware update. Matching interrupted MIDI updates can resume; ROM UBOOT is a separate documented recovery route. Our current firmware is listed with installation disabled while its own OTA and physical recovery are unqualified. [Full workflow and limitations](HARDWARE_INSTALLER.md).
